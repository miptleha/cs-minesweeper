## Общее для всех UI-фаз (Phase 5–46)

Единые правила для каждого UI, чтобы не повторять их в каждой фазе:

1. **Архитектура.** UI — тонкий слой поверх готового `GameEngine`. Никаких
   изменений в `MinesweeperCore`: если UI нужны новые данные — это баг UI, не ядра.
2. **Раскладка ввода** — по §6.1 `09-PHASE-5-WINFROMS.md`: ЛКМ = `OpenCell`,
   ПКМ = `CycleMark`, Ctrl+ЛКМ = `CycleMark`, ЛКМ+ПКМ или средняя кнопка = `Chord`,
   клик по смайлику = `StartNewGame`. Поведение одинаково во всех UI.
3. **Смайлик и LED-счётчики** — как в WinForms/MonoGame: `smiley_oh` при `MouseDown`
   на поле, `smiley_win`/`smiley_lose` по `GameStateChanged`, `minus.png` + две
   цифры при отрицательном `RemainingMines`.
4. **Ассеты** — общие из `assets/`, имена файлов не меняются; в проект копируются
   по конвенции фреймворка (см. `04-AGENT-GUIDE.md`, раздел «Shared Assets»).
5. **Рекорды** — общий `JsonRecordStore` из `MinesweeperCore.Infrastructure`,
   единый `%LocalAppData%\Minesweeper\records.json` для всех версий: рекорд,
   поставленный в WPF, виден в WinForms и наоборот.
6. **Решение.** Каждый новый проект добавляется в `Minesweeper.slnx` под `/src/`
   с `ProjectReference` на `MinesweeperCore.csproj`.
7. **Release.** Self-contained, `win-x64`, как в существующих проектах — за
   исключением Godot и Stride, где итоговую сборку делает сам движок.

## Первые UI (Phase 5–6)

### Phase 5: WinForms — ✅ Готово (0.2.0)

Самый старый нативный тулкит .NET: императивный API (`Controls.Add`), отрисовка
через GDI+, встроен в SDK — зависимостей нет. Агент знает его идеально, поэтому
первый UI получился за один подход. Для минёра удобен всем, кроме двух вещей:
Windows-only и слабое DPI-масштабирование, которое пришлось чинить вручную
(патчи 0.2.1–0.2.2).

### Phase 6: MonoGame — ✅ Готово (0.3.0)

Игровой фреймворк — наследник XNA: фиксированный игровой цикл, спрайты,
Content Pipeline, шрифты через `spritefont`. UI здесь рисуется руками: поле,
LED-счётчики, смайлик и даже меню — всё на спрайтах (экранная машина состояний
`Main` / `Records` / `About` / `NamePrompt`). Для пиксель-арта минёра — идеально
(`SamplerState.PointClamp`), для меню и диалогов — трудозатратно. «Фреймворк, а
не движок»: прозрачно и быстро.

## Дополнительные UI-проекты (Phase 7–9)

### Phase 7: WPF — ✅ Готово (0.4.0)

«WinForms 2.0» от Microsoft: декларативный XAML, Data Binding, MVVM, рендер через
DirectX. Десятилетия развития — тысячи примеров, агент генерирует рабочий код с
первого прохода. Для минёра удачно: сетку поля собирает `ItemsControl` +
`UniformGrid` + `DataTemplate`, ассеты подключаются через `BitmapImage`.
Только Windows; это входная точка в XAML-семейство.

### Phase 8: Avalonia — ✅ Готово (0.5.0)

Кроссплатформенный XAML: синтаксис почти совпадает с WPF, поэтому после Phase 7
это практически бесплатный вариант — те же биндинги, стили и шаблоны. Рендер
через SkiaSharp, ассеты через `IImage`. Бонус — сборка self-contained и Native
AOT (`-p:PublishAot=true`). Минус: экосистема меньше, чем у WPF, свои тонкости
в темах и DPI.

### Phase 9: Blazor Hybrid — ✅ Готово (0.6.0)

Смена парадигмы: компоненты Razor (HTML/CSS + C#) внутри WebView2. Для минёра
поле — это просто HTML-таблица или CSS-grid, стили достаются бесплатно.
Неудобства: рантайм тяжёлый (WebView2 Runtime не входит в self-contained exe),
а взаимодействие C# ↔ DOM ограничено `IJSRuntime` и `@onclick`. Хороший мостик
в веб-стек.

## Дальнейшие фазы: от популярных к экспериментальным (Phase 10–35)

**Принцип порядка.** Новые фазы отсортированы по востребованности технологии:
сначала то, на чём пишут тысячи разработчиков и что активно развивается, затем —
нишевые библиотеки и эксперименты. Ориентиры — число звёзд GitHub и активность
разработки (данные на 2026-11-20) плюс актуальность для десктопных C#-приложений.
Минёр не обязан появиться во всех фазах: фазы с ⚠️ «под вопросом» и 🧪
«эксперимент» выполняются по желанию, а непопулярные — последними.

**Эшелоны:**

- **Эшелон 1 — мейнстрим** (Phase 10–15): .NET MAUI, Godot .NET, WinUI 3,
  Terminal.Gui, Uno Platform, Stride.
- **Эшелон 2 — популярные ниши** (Phase 16–21): SkiaSharp + Silk.NET, Eto.Forms,
  FNA + MGCB, ImGui.NET, raylib-cs, Photino.NET.
- **Эшелон 3 — нишевые и официальные эксперименты** (Phase 22–26): Myra,
  Hawkynt.NativeForms, CoreWindowsWrapper, LVGLSharp, Microsoft.UI.Reactor.
- **Эшелон 4 — низкоуровневое и устаревшее** (Phase 27–28): TerraFX, UWP.
- **Эшелон 5 — экспериментальные фреймворки** (Phase 29–31): Duxel, Lumi, MewUI.
- **Эшелон 6 — библиотеки готовых контролов и UI-наборы** (Phase 32–46): Jalium.UI,
  AtomUI, Siticone UI, Nevron Open Vision, Krypton Toolkit, AntdUI, ReaLTaiizor,
  SunnyUI и семь бесплатных WPF-наборов (Phase 40–46). Технологии, которые дают
  красивые элементы интерфейса поверх существующих фреймворков. Phase 36–39 —
  бесплатные аналоги коммерческих наборов контролов уровня DevExpress для
  WinForms; Phase 40–46 — темы, стилизация и недостающие контролы для
  WPF-версии (Phase 7): меню, таблицы, диалоги и современный облик.

### Phase 10: .NET MAUI — ⬜ Запланировано

~23 300 ★ (`dotnet/maui`), активная разработка — главный кроссплатформенный
фреймворк Microsoft (Windows / macOS / iOS / Android), поэтому идёт первым.
XAML и MVVM близки к WPF, но своя иерархия контролов и система обработчиков
(handlers). Для минёра: стандартный self-contained `dotnet publish`; минус —
тяжёлый workload и медленные сборки. Осваивается как самый востребованный
XAML-стек на рынке.

### Phase 11: Godot .NET — ⚠️ Под вопросом (сборка через движок)

~120 000 ★ (`godotengine/godot`) — крупнейшее C#-сообщество в геймдеве. Нодовая
модель сцены, редактор, `_Process` / `_Input`; 2D — стихия Godot, минёру подходит
отлично. Слабое место — сборка: экспорт пресетами самого движка, а не
`dotnet publish`, поэтому классический self-contained exe нецелевой. Плюс порог
входа выше: редактор и его культура. Фаза под вопросом именно из-за пайплайна
сборки, не из-за технологии.

### Phase 12: WinUI 3 — ⬜ Запланировано

~4 700 ★ (`microsoft/WindowsAppSDK`), активно развивается Microsoft: официальный
современный нативный UI Windows и преемник UWP. Fluent-дизайн из коробки, XAML
нового поколения, свежая интеграция с системой. Для минёра — редизайн под Fluent.
Минусы: экосистема моложе и шершавее WPF, упаковка обычно MSIX. Зато навыки
напрямую переиспользуются в Uno (Phase 14).

### Phase 13: Terminal.Gui — ⬜ Запланировано

~11 300 ★ (`gui-cs/Terminal.Gui`) — самый популярный консольный UI-фреймворк
.NET, активно развивается. `Application` / `Window` / `MenuBar`, вьюхи и диалоги
в терминале; ввод клавиатурный, мышь вторична. Для минёра: поле и LED-счётчики
рисуются псевдографикой — неожиданно органично, а пиксель-арт ассеты не нужны
вообще. Самый лёгкий exe и нулевые графические зависимости.

### Phase 14: Uno Platform — ⬜ Запланировано

~10 100 ★ (`unoplatform/uno`), активная разработка. Тот же WinUI-совместимый
XAML-API, что в Phase 12, но на всех платформах и через Skia-рендеринг. Для
минёра — почти переиспользование навыков Phase 12. Минус: самый замысловатый
шаблон проекта среди XAML-фреймворков (`Uno.Sdk`). Полезно для осознанного
выбора между Uno, Avalonia и MAUI.

### Phase 15: Stride — ⚠️ Под вопросом (тяжёлая сборка)

~7 900 ★ (`stride3d/stride`) — самый популярный чисто-C# игровой движок, активно
развивается. Сцены, Entity-компоненты, полноценный редактор; сила — 3D, для
плоского минёра избыточен. Сборка через редактор, self-contained нетривиален —
как и Godot, выбивается из пайплайна `dotnet publish`. Осваивается скорее ради
опыта «движок против библиотеки».

### Phase 16: SkiaSharp + Silk.NET — ⬜ Запланировано

~5 600 ★ (`mono/SkiaSharp`) и ~5 300 ★ (`dotnet/Silk.NET`), оба активно
развиваются. Никакого UI-фреймворка: `SKCanvas` для рисования, окно, ввод и
игровой цикл — своими руками через GLFW-биндинги Silk.NET. Для минёра удобно:
полный контроль над отрисовкой и понимание того, что происходит «под капотом»
у любого GUI. Минус: меню и диалоги придётся писать самому — трудоёмко.

### Phase 17: Eto.Forms — ⬜ Запланировано

~3 800 ★ (`picoe/Eto`), ~957 тыс. загрузок NuGet — зрелая кросс-платформенная
абстракция, использующая WinForms как один из бэкендов (наряду с WPF, GTK,
Cocoa). Для минёра — сравнение с Avalonia (Phase 8): Eto легче и старее, но
даёт прямой доступ к WinForms-бэкенду на Windows. Стабильные пакеты
`Eto.Forms` и `Eto.WinForms` доступны на NuGet.

### Phase 18: FNA + MGCB — ⬜ Запланировано

~3 100 ★ (`FNA-XNA/FNA`), активная разработка. XNA4-совместимый рантайм с упором
на точность и кроссплатформенность; API почти идентичен MonoGame, поэтому после
Phase 6 вход мгновенный. MGCB — Content Builder для ассетов, интересное сравнение
с Content Pipeline MonoGame. Для минёра — лёгкий вариант «то же, но чуть иначе».

### Phase 19: ImGui.NET — ⬜ Запланировано

~2 300 ★ (`ImGuiNET/ImGui.NET`); сам Dear ImGui — стандарт индустрии для
инструментов и отладочных UI. Immediate-mode: никаких виджетов и подписок на
события — каждый кадр весь UI описывается заново. Для минёра идеален по духу
(клетки и так перерисовываются каждый кадр); нужен лишь рендер — берётся Silk.NET
из Phase 16. Минус: нет классического десктоп-облика.

### Phase 20: raylib-cs — ⬜ Запланировано

Биндинги ~1 500 ★ (`raylib-cs/raylib-cs`); сам raylib — десятки тысяч звёзд,
«самая простая игровая библиотека». Плоский API в одном пакете: окно, ввод и
2D-отрисовка вместе (`InitWindow`, `DrawTexture`). Для минёра — самый короткий
путь от нуля до окна с игрой. Минус: простота оборачивается тем, что весь UI
опять надстраивается руками.

### Phase 21: Photino.NET — ⬜ Запланировано

~1 400 ★ (`tryphotino/photino.NET`); активность снизилась (последний коммит —
начало 2026), но проект жив. Минимальная оболочка над системным web-view:
HTML/CSS UI без Blazor и без тяжёлого бэкпака. Для минёра: разметку из Phase 9
можно перенести почти как есть — сравнение «Blazor Hybrid vs чистый web-view».
Минус: API предельно минимален — ни компонентов, ни биндинга, всё руками.

### Phase 22: Myra — ⬜ Запланировано

~890 ★ (`rds1983/Myra`) — UI-библиотека специально для MonoGame, FNA и Stride.
Готовые виджеты (`Desktop`, `Grid`, меню) поверх знакомого рантайма — самый
быстрый и естественный эксперимент после Phase 6. Для минёра: снимает главную
боль MonoGame — ручные меню и диалоги. Минус: нишевое применение, вне игровых
движков практически не встречается.

### Phase 23: Hawkynt.NativeForms — ⬜ Запланировано

`Hawkynt.NativeForms` — стабильный пакет (версия 1.0.x), trim- и
AOT-совместимый UI-тулкит с API, повторяющим Windows Forms, но рендерящим через
нативные виджеты платформы (Win32, GTK, Cocoa) посредством P/Invoke. Это не
надстройка над WinForms, а самостоятельная реализация с тем же стилем кода.
Для минёра — прямой кандидат на «WinForms-подобное окно без
`System.Windows.Forms`» с сохранением знакомой модели `Controls.Add` и
обработчиков событий. Популярность пока невысокая (~8 тыс. загрузок NuGet), но
пакет стабильный и заслуживает проверки.

### Phase 24: CoreWindowsWrapper — ⬜ Запланировано

`CoreWindowsWrapper` — небольшая библиотека, которая создаёт нативные окна и
диалоги напрямую через Windows API, явно без `System.Windows.Forms`. Стабильная
ветка 1.x доступна; ветка 2.x пока в prerelease. Для минёра — минималистичный
вариант чистого Win32-окна с заголовком и иконкой, без лишних абстракций.
Хорошая образовательная точка: видно, сколько «магии» на самом деле скрывает
WinForms. Популярность невысокая (~18 тыс. загрузок, ~13 звёзд GitHub), но
проект живой.

### Phase 25: LVGLSharp — ⬜ Запланировано

`LVGLSharp` — слой совместимости с WinForms API, который рендерит через LVGL.
Основной пакет `LVGLSharp.Forms` опубликован на NuGet и поддерживает `net10.0`
и `net10.0-windows`. Цель проекта — позволить интерфейсам, свёрстанным в
WinForms Designer, работать на Linux и встраиваемых платформах (arm/arm64).
Для минёра — проверка, насколько далеко можно уйти от Windows, сохраняя
WinForms-подобный код. Популярность пока низкая (~1,4 тыс. загрузок, ~23 звезды
GitHub), но направление интересное.

### Phase 26: Microsoft.UI.Reactor — 🧪 Эксперимент

~900 ★ (`microsoft/microsoft-ui-reactor`) — официальный эксперимент Microsoft:
React-подобные расширения над WinUI. Компоненты и hooks меняют взгляд на XAML:
UI описывается функцией, а не разметкой. Для минёра — маленький, но передовой
проект: знакомство с React-паттерном без выхода из C#. Минус: экспериментальный
статус — API может меняться без предупреждения.

### Phase 27: TerraFX — 🧪 Эксперимент

~320 ★ (`TerraFX/TerraFX`). Не UI-фреймворк, а низкоуровневые биндинги
мультимедиа-стека Windows (D3D12 и др.). Для минёра — максимальная
образовательная ценность: окно и отрисовка поля почти напрямую через графический
API. Практическая ценность минимальна, трудоёмкость максимальна — потому в конце.

### Phase 28: UWP — ⚠️ Под вопросом (устарела)

Платформа фактически свёрнута: Microsoft перенесла фокус на WinUI 3 /
Windows App SDK (Phase 12). Сборка требует UWP-ворклоада, упаковка и подпись
MSIX, self-contained exe в классическом смысле не получается. Для минёра —
исторический интерес: XAML в песочнице MSIX. Кандидат на пропуск.

### Phase 29: Duxel — 🧪 Эксперимент

Immediate-mode GUI: лёгкий, ориентирован на Native AOT. Почти неизвестен —
мало обучающих данных, интерес скорее исследовательский. Для минёра: сравнение
с ImGui.NET (Phase 19) — два immediate-mode подхода лицом к лицу. Риск: API
может сломаться посреди разработки.

### Phase 30: Lumi — 🧪 Эксперимент

HTML/CSS как язык разметки, но рендеринг нативный — через SkiaSharp, без
браузера. «Лёгкий Blazor»: молодая экосистема, агент знает её хуже всего.
Для минёра: третья точка в сравнении web-подходов — Blazor Hybrid (Phase 9),
Photino (Phase 21), Lumi. Интересно сравнить размер и скорость запуска.

### Phase 31: MewUI — 🧪 Эксперимент

NativeAOT-ориентированный GUI: self-contained exe 3–4 MB — демонстрация того,
насколько «крошечным» может быть .NET-десктоп. Проект самый молодой и
нестабильный в списке; агент знает его хуже всех. Для минёра — чистый эксперимент
на грани исследования, финальная точка роадмапа.

## Библиотеки готовых контролов (Phase 32–39)

### Phase 32: Jalium.UI — ⬜ Запланировано

Современный WPF-подобный фреймворк для .NET 10 с рендерингом через DirectX 12 / Vulkan.
Предоставляет более 120 готовых контролов, включая `Button`, `TextBox`, `MenuBar`,
`ToolBar`, `Image`, а также сложные `DataGrid` и `Ribbon`. Модель программирования
знакома: Dependency Properties, Data Binding, MVVM. Для минёра — отличная возможность
собрать интерфейс из готовых кирпичиков, используя привычный подход. Минус: проект
новый, API может меняться.

### Phase 33: AtomUI — ⬜ Запланировано

Библиотека готовых контролов и тем в стиле Ant Design для Avalonia UI. Предоставляет
полный набор элементов: кнопки, поля ввода, выпадающие списки, навигацию, иконки,
`DataGrid`. Для минёра — самый быстрый способ получить современный, красивый интерфейс,
не отвлекаясь на стилизацию. Идеально подходит для тех, кто выбрал Avalonia (Phase 8),
но хочет сэкономить время на дизайне.

### Phase 34: Siticone UI — ⬜ Запланировано

Библиотека современных, аппаратно-ускоренных контролов для классического WinForms.
Содержит более 280 элементов: современные кнопки, переключатели, таблицы, гриды, меню,
прогресс-бары. Для минёра — способ сохранить простоту и скорость разработки WinForms
(Phase 5), но убрать его «устаревший» вид. Позволяет создавать красивые интерфейсы
без ручной отрисовки.

### Phase 35: Nevron Open Vision — ⬜ Запланировано

Тяжёлый коммерческий enterprise-фреймворк, предоставляющий единый набор из 70+
контролов для WinForms, WPF, Blazor и Mac. Включает Ribbon, панели инструментов,
меню, навигационные панели, диалоговые окна. Для минёра — это, скорее, избыточный
вариант, но он демонстрирует, как выглядит профессиональный набор «всё-в-одном»
для деловых приложений. Если понадобится Ribbon-интерфейс или сложные диалоги —
это хороший кандидат.

### Phase 36: Krypton Toolkit — ⬜ Запланировано

Самый близкий бесплатный аналог коммерческих наборов уровня DevExpress: прямое
продолжение Component Factory Krypton, лицензия BSD-3-Clause, ~620 ★, активная
разработка — релиз V110.00 за ноябрь 2026. Поддерживает .NET Framework
4.6.2–4.8.1 и .NET 8–10; в составе пять продуктов — Toolkit, Ribbon, Navigator,
Workspace, Docking, плюс Extended Toolkit с дополнительными контролами.
`KryptonMessageBox` — drop-in замена стандартного `MessageBox`. Для минёра —
минимальный вход: проект WinForms (Phase 5) пересаживается на Krypton-форму и
Krypton-контролы почти без изменений кода, но получает современную тему и
систему палитр.

### Phase 37: AntdUI — ⬜ Запланировано

WinForms-библиотека в дизайн-языке Ant Design: ~1,1 тыс. ★, Apache-2.0,
активная разработка (коммиты осени 2026). Чистая векторная графика на GDI без
картиночных ресурсов, качественный антиалиасинг, тени, прерываемые анимации,
безрамочные окна с нативным поведением; полностью поддерживает Native AOT и
таргетится на .NET Framework 4.0/4.8 и .NET 8/10. Для минёра — самый
«вебоподобный» облик среди WinForms-наборов: клетки поля и счётчики легко
собираются штатными контролами AntdUI.

### Phase 38: ReaLTaiizor — ⬜ Запланировано

~2,3 тыс. ★, MIT: «дизайн-ориентированная» библиотека контролов для WinForms с
множеством самостоятельных тем (Material, Metro, Fluent и другие). Для минёра —
быстрая смена облика WinForms-версии без переписывания логики; интересно
сравнить несколько тем друг с другом. Минус: это скорее набор скинов и
современных виджетов, чем «тяжёлых» контролов уровня DevExpress-гридов — по
духу ближе к Siticone UI (Phase 34).

### Phase 39: SunnyUI — ⚠️ Под вопросом (лицензия GPL-3.0)

~2,5 тыс. ★ — самая популярная бесплатная WinForms-библиотека в списке: набор
контролов, утилит и многостраничный фреймворк (`UIForm` / `UIPage` / `UIFrame`)
в стиле Element; .NET Framework 4.0+ и .NET 6/8/10, активная разработка (2026).
Фаза под вопросом не из-за качества, а из-за лицензии: GPL-3.0 «вирусна» —
использование допустимо, только если сам минёр распространяется под
GPL-совместимой лицензией. Для открытого экспериментального проекта — сильный
кандидат; для закрытого — нет.

## Библиотеки готовых контролов для WPF (Phase 40–46)

Продолжение эшелона 6 поверх уже готовой WPF-версии (Phase 7). Уточнение:
базовые контролы в WPF есть — `Menu`, `ContextMenu`, `DataGrid`, `Button` —
но их вид по умолчанию остался на стиль 2000-х, а часть удобных элементов
(снекбары, нефбе-диалоги, `PropertyGrid`) действительно отсутствует. Ниже —
бесплатные наборы, которые закрывают обе задачи. Все пакеты подключаются
к проекту net10.0-windows через NuGet; лицензии — MIT, кроме двух фаз
с пометкой «под вопросом».

### Phase 40: Material Design in XAML — ⬜ Запланировано

~16,3 тыс. ★ (`MaterialDesignInXAML/MaterialDesignInXamlToolkit`), MIT — самый
популярный и самый живой WPF-набор из списка: релиз 5.4.0 за октябрь 2026.
Два пакета: `MaterialDesignThemes` и `MaterialDesignColors`. Стили Material
Design (включая актуальный Material 3) для всех базовых контролов WPF —
меню, `DataGrid`, кнопок, диалогов — плюс собственные карточки, `DialogHost`,
снекбары и полный пак иконок Material Design Icons. Подключается ресурсными
словарями в `App.xaml`, поэтому XAML-разметка Phase 7 почти не меняется.
Для минёра — быстрый перевод WPF-версии на современный облик с нормальными
диалогами и меню. Работает и в связке с MahApps (Phase 41).

### Phase 41: MahApps.Metro — ⬜ Запланировано

~9,8 тыс. ★ (`MahApps/MahApps.Metro`), MIT — старейший и самый зрелый WPF-тулкит:
стабильная 2.4.11 (сентябрь 2025), ветка 3.0 в release candidate с хромированием
окна под Windows 11. Его идея — не новые контролы, а переоформление стандартных:
Button, TextBox, Menu, DataGrid получают современный Metro-вид, а `MetroWindow`
добавляет корректную рамку окна, Flyout-панели и нефбе-диалоги (`DialogCoordinator`)
взамен блокирующих `MessageBox`. Официально таргетируется .NET 6/8 — на .NET 10
пакет подтягивается через совместимость таргетов. Для минёра — минимальный вход:
окно Phase 7 становится `MetroWindow`, XAML меняется точечно.

### Phase 42: WPF UI (Fluent) — ⬜ Запланировано

~9,6 тыс. ★ (`lepoco/wpfui`), MIT, активная разработка (4.3.0 — май 2026;
поддержка .NET 10 появилась с версии 4.1.0). Переносит Fluent-дизайн
Windows 11 в WPF: темы с Mica-эффектом, `NavigationView`, NumberBox, InfoBar,
Dialog, Snackbar, SymbolIcon из шрифта Segoe Fluent. Отдельное
приложение-галерея в Microsoft Store позволяет проверить каждый контрол.
Для минёра — самый «системный» облик: окно и контролы выглядят как нативные
приложения Windows 11. Минус: проект держится в основном на одном мейнтейнере.

### Phase 43: HandyControl — ⚠️ Под вопросом (медленные релизы)

~7,2 тыс. ★ (`HandyOrg/HandyControl`), MIT — «контролы на каждый день»:
большой набор готовых элементов и тем — вкладки с закрытием, диалоги, пикеры,
`NumericUpDown`, богатые списки. Коммиты в мастер идут (июнь 2026), но
стабильная версия — 3.5.1 от марта 2024, дальше только rc (3.6.0-rc3,
сентябрь 2025): между релизами разрывы больше года. Для минёра — запасной
вариант против Phase 40–42; под вопросом из-за темпа релизов, не из-за качества.

### Phase 44: ModernWpf — ⬜ Запланировано

~4,9 тыс. ★ (`Kinnara/ModernWpf`), MIT. История запутанная: линия 0.9.x
заморожена и официально объявлена неподдерживаемой, но в 2026-м проект ожил —
активная ветка 1.0.0-rc.1 таргетируется на `net10.0-windows7.0` и подключает
официальные Fluent-ресурсы WPF для базовых контролов. Даёт WinUI-подобные
стили, `WindowHelper.UseModernWindowStyle` для окна и галерею ModernWpf.Gallery
как образец. Для минёра — второй Fluent-подход на сравнение с WPF UI (Phase 42).
Минус: 1.x ещё в rc — API между кандидатами может меняться.

### Phase 45: Extended WPF Toolkit — ⚠️ Под вопросом (лицензия)

Набор от Xceed: 48 контролов, которых в WPF нет — `PropertyGrid`,
`DateTimePicker`, `NumericUpDown`, `CheckComboBox`, `CheckListBox`,
`ColorPicker`, `AvalonDock`. Активно поддерживается (5.1.2 — июнь 2026).
Фаза под вопросом не из-за качества, а из-за лицензии: начиная с v4.0.0
бесплатная Community-лицензия разрешает только некоммерческое использование —
для учебного минёра это допустимо, но ограничение нужно знать заранее.
Хорошее дополнение к любой из фаз 40–44: те дают облик, этот — «недостающие»
контролы.

### Phase 46: Panuon.WPF.UI — 🧪 Эксперимент

~1,3 тыс. ★ (`Panuon/Panuon.WPF.UI`), Apache-2.0. Своё направление: не набор
готовых контролов, а движок кастомизации — attached properties перекраивают
стандартные контролы почти без XAML-шаблонов. Для минёра — эксперимент в
обратную сторону от фаз 40–44: вместо стилизации сверху — управление скинами
из кода. Минусы: документация только на китайском, последний релиз ядра
вышел в 2022-м — развитие практически остановилось.

## Дисклеймер

**Обязательные фазы (1–9) выполнены.** Дальше — тридцать семь опциональных
UI-вариантов (Phase 10–46): порядок задан популярностью и актуальностью
технологий, а не полнотой покрытия. Фазы с ⚠️ «под вопросом» (Godot, Stride,
UWP, HandyControl, Extended WPF Toolkit, SunnyUI) — вероятные кандидаты
на пропуск из-за нетипичной сборки, затухшего развития или ограничений лицензии.
После каждой фазы полезно ответить на вопросы:

- Что нового дала технология по сравнению с предыдущими?
- Насколько просто было интегрировать `GameEngine`?
- Есть ли что-то, что было бы удобнее в ядре, но ради чистоты архитектуры
  оставили как есть?

Эти ответы — главный результат эксперимента, а не количество готовых UI.
