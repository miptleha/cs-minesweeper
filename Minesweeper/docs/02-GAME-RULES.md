# 02 — Правила игры (классический «Сапёр» Windows XP)

Этот документ — **единственный источник истины** для бизнес-логики ядра `MinesweeperCore`. 
Правила описывают состояние игрового мира и переходы между состояниями. Визуализация (цвета, спрайты, звуки) описана в UI-проектах и не входит в этот документ.

---

## 1. Игровое поле

*   Поле — **прямоугольная сетка клеток** размером `Width × Height`.
*   Координаты клетки: `(x, y)`, где `x` — столбец, `y` — строка. Начало координат `(0, 0)` — верхний левый угол.
*   **Классические границы** для пользовательского режима: **9 × 9** .. **30 × 24**.
    UI-проекты используют их в Custom-диалоге (см. `09-PHASE-5-WINFROMS.md` §11).
*   **Технические границы** `GameSettings`: **3 × 3** .. **1000 × 1000**.
    Нужны для `PerformanceTests.Stress_1000x1000With100kMines_...` и для юнит-тестов
    маленьких полей (3×3, 5×5). Ядро допускает `3 × 3`, но UI не обязан это разрешать.
*   Максимальное количество мин для поля `A × B` — `(A − 1) × (B − 1)`.

## 2. Мины

*   На поле размещается заданное количество **мин** (`MineCount`).
*   Мины размещаются **случайно**.
*   Количество мин должно удовлетворять условию: `0 ≤ MineCount ≤ (Width − 1) × (Height − 1)`.
*   **Реализация в ядре:** Генерация мин должна использовать `IRandomProvider`.

## 3. Состояние клетки (`CellState`)

1.  **`Closed` (Закрыта)** — игрок не знает содержимого.
2.  **`Opened` (Открыта)** — игрок видит содержимое.
3.  **`Flagged` (Флаг)** — закрытая клетка с меткой «мина».
4.  **`Question` (Вопрос)** — закрытая клетка с меткой «возможно, мина».
    Мягкая метка, не блокирует открытие.
5.  **`WrongFlag` (Ошибочный флаг)** — терминальное состояние при
    поражении, если на безопасной клетке был `Flagged` (см. §16.2).

*   Открытая клетка **не может** быть помечена меткой.
*   Метка меняется циклически правым кликом — см. §7.

## 4. Содержимое клетки (`CellContent`)

Для открытой клетки определено содержимое:
*   **`Mine` (Мина)** — символ взрыва.
*   **`Number` (Цифра)** — количество мин среди соседей (от 1 до 8).
*   **`Empty` (Пусто)** — 0 мин среди соседей (визуально пустая клетка).

*Соседние клетки — до 8 клеток, окружающих данную (по горизонтали, вертикали и диагонали).*

## 5. Первый ход (Критически важное правило)
*   **Первая открытая клетка в игре никогда не содержит мину.**
*   **Реализация в ядре (Ленивая генерация):** Вместо того чтобы генерировать
    поле и «перемещать» мину, ядро должно генерировать мины **только при первом
    вызове `OpenCell`**. При этом клетка первого клика исключается из списка
    доступных для расстановки мин. Соседи первого клика могут содержать мины —
    это классическое поведение Windows XP.
*   **Следствие:** первый клик **не гарантирует** каскадное открытие. Если
    рядом с кликнутой клеткой есть мина, клетка откроется как `Number` (1–8),
    каскада не будет. Если мин рядом нет — клетка `Empty`, запускается каскад.
    Оба варианта — норма.


## 6. Открытие клетки (`OpenCell` — левый клик)

Игрок открывает клетку левым кликом.
*   Клик по `Flagged` или `Opened` игнорируется (без выброса исключений).
*   Клик по `Question` разрешён — клетка открывается как обычная.
*   **6.1. Попадание на мину (`Mine`):**
    *   Игра немедленно завершается **Поражением**.
    *   Все мины на поле становятся `Opened`.
    *   Неверно поставленные флаги (на безопасных клетках) помечаются как ошибочные.
*   **6.2. Безопасная клетка с `N > 0` (`Number`):**
    *   Клетка открывается. Отображается цифра.
*   **6.3. Безопасная клетка с `N = 0` (`Empty`):**
    *   Клетка открывается (пустая).
    *   Запускается **каскадное открытие** (Flood Fill): открываются все соседние закрытые клетки, **кроме помеченных флагом**.
    *   Если среди них есть пустые (`N = 0`), каскад продолжается.
    *   Каскад останавливается на цифрах (`Number`).
    *   **Реализация в ядре:** Алгоритм должен быть **итеративным** (через `Queue` или `Stack`), чтобы избежать `StackOverflow` на больших полях.

## 7. Метки клеток (`CycleMark` — правый клик)

*   **Ограничение:** метки можно ставить до первого открытия. Левый клик по
    `Flagged`-клетке в состоянии `NotStarted` игру **не запускает** — ни
    `PlaceMines`, ни `BoardGenerated`, ни таймер. Игра остаётся `NotStarted`.

Правый клик циклически переключает метку закрытой клетки через три состояния:

1.  `Closed` (без метки) →
2.  `Flagged` (флаг «мина») →
3.  `Question` (знак вопроса «возможно, мина») →
4.  обратно в `Closed`.

*   Метки можно ставить/снимать только на клетках в состоянии `Closed`,
    `Flagged` или `Question`. Правый клик по `Opened` или `WrongFlag`
    не делает ничего.
*   **Ограничение:** Правила классики позволяют ставить больше флагов,
    чем мин (счётчик может уходить в минус). Ядро просто хранит состояние
    метки, не ограничивая количество флагов.
*   **Флаг (`Flagged`)** блокирует открытие левым кликом **и** каскадное
    открытие (каскад пропускает клетки с флагом).
*   **Вопросительный знак (`Question`)** — это «мягкая» метка. Она
    **не блокирует** ни открытие левым кликом, ни каскадное открытие.
    Игрок сам решает, когда открыть клетку — знак нужен только как
    временная пометка «здесь может быть мина».
*   **UI-примечание:** метка ставится правым кликом **или** Ctrl+ЛКМ (для
    устройств без рабочего правого клика). Оба пути вызывают `CycleMark`.
    Полная раскладка ввода — `09-PHASE-5-WINFROMS.md` §6.1.

## 8. Условие победы (`Won`)

*   Игра выиграна, когда **все безопасные клетки открыты**.
*   Наличие флагов на минах **не требуется**.
*   **Реализация в ядре:** Переход в состояние `Won` происходит сразу после
    открытия последней безопасной клетки. Ядро эмитит `GameStateChanged` с
    `NewState = Won` и `TriggerCell = null`. Ядро **не изменяет** состояние
    клеток-мин на победе — они остаются `Closed` или `Flagged`.
*   **Что делает UI на `Won`:** перерисовывает всё поле, рисуя `cell_flag.png`
    поверх всех клеток, которые остались в состоянии `Closed` или `Flagged`.
    При `Won` гарантируется, что все такие клетки — мины (условие победы
    требует, чтобы все безопасные клетки были `Opened`). Подробности —
    §16.1.

## 9. Условие поражения (`Lost`)

*   Игра проиграна при открытии мины.
*   Переход в `Lost` немедленный.
*   После поражения ввод игнорируется (методы `OpenCell` и `CycleMark`
    ничего не делают, пока не вызван `StartNewGame`).
*   **Реализация в ядре:** Ядро открывает **все мины** на поле и помечает
    **все ошибочные флаги** как `WrongFlag`. Триггерная клетка (на которую
    кликнули) эмитится через `CellChanged`, все остальные изменения — через
    один `CellsRevealed`. `GameStateChanged` получает `NewState = Lost` и
    `TriggerCell = CellInfo` триггерной клетки. Подробная таблица —
    §16.2.

## 10. Состояния игры (`GameState`)

*   **`NotStarted` (Не начата):** Поле сгенерировано (или пустое), ни одна клетка не открыта.
*   **`InProgress` (В процессе):** Открыта хотя бы одна клетка, игра не завершена.
*   **`Won` (Победа):** Условие победы выполнено.
*   **`Lost` (Поражение):** Открыта мина.

*Переходы: `NotStarted -> InProgress` (первый клик), `InProgress -> Won`, `InProgress -> Lost`. Из `Won`/`Lost` переходов нет.*

## 11. Новая игра (`StartNewGame`)

*   Сбрасывает всё: новое поле, новые мины (лениво), все клетки `Closed`, счётчики сброшены, таймер обнулен, состояние `NotStarted`.

## 12. Уровни сложности и настройки

### 12.1. Фиксированные уровни

| Уровень | Ширина | Высота | Мин |
|---|---|---|---|
| Новичок (Beginner) | 9 | 9 | 10 |
| Любитель (Intermediate) | 16 | 16 | 40 |
| Профессионал (Expert) | 30 | 16 | 99 |

### 12.2. Пользовательский режим (Custom)

*   **Классические границы для UI**: Ширина 9..30, Высота 9..24. UI-диалог
    Custom ограничивает ввод этими значениями.
*   **Технические границы ядра** (`GameSettings`): Ширина 3..1000, Высота 3..1000.
    Нужны для стресс-тестов и юнит-тестов маленьких полей. UI не должен
    разрешать эти границы игроку.
*   Мины: `0..(Width − 1) × (Height − 1)`. Ядро допускает 0 мин (тесты,
    каскадные сценарии). UI-проекты могут ограничивать минимум для
    Custom-режима (например, 10) на уровне своего диалога настроек.

## 13. Таблица рекордов (`Records`)

*   Хранится **Топ-5** лучших времён для каждого из **трёх фиксированных уровней**.
*   Запись содержит: время (в секундах) и имя игрока (`GameEngine.PlayerName`).
*   Обновляется **только при победе** на фиксированном уровне.
*   Пользовательский режим (Custom) в таблицу не попадает.
*   **Реализация в ядре:** Сохранение и загрузка осуществляются через порт `IRecordStore`. Ядро не знает, куда сохраняются рекорды (в файл, БД или реестр).

## 14. Таймер (`Elapsed`)

*   Запускается с первого открытия клетки (`NotStarted -> InProgress`).
*   Останавливается при победе или поражении.
*   **Реализация в ядре:** Ядро предоставляет свойство `Elapsed` (`TimeSpan`). Прямое использование `System.DateTime.UtcNow` в ядре **запрещено** — только через порт `ITimeProvider` (см. `03-ARCHITECTURE.md`, раздел «Abstractions»). Это требование детерминизма тестов (см. `07-TESTING.md` §2).
*   **Фиксация времени при завершении партии:** переход `InProgress → Won` или `InProgress → Lost` **обязан** зафиксировать `_elapsed = Elapsed` **до** смены `GameState`. Иначе после победы `Elapsed` вернёт `0`, и рекорд сохранится с нулевым временем.

## 15. Контракт с UI (Что не входит в правила)

Следующее относится к слою представления:
*   Внешний вид клеток, анимации, звуки.
*   Отрисовка таймера и счётчика мин.
*   Окна диалогов (О программе, Лучшие результаты).
*   Способ ввода (мышь, тач, клавиатура).

**Правило для UI-проектов:** UI не должен содержать логику игры. Он только вызывает методы ядра (`OpenCell`, `CycleMark`) и отрисовывает данные, полученные из `CellInfo` и событий (`CellChanged`, `CellsRevealed`).

**Счётчик мин в UI** — это `GameEngine.RemainingMines = MineCount − количество поставленных флагов`. Счётчик отражает **действия игрока**: флаг, поставленный правым кликом и не снятый, уменьшает значение на 1; снятый — увеличивает. При `Won` и `Lost` счётчик **не меняется** (игрок своих действий не отменял). Клетки в состоянии `Question` **не считаются** флагами. Если `количество флагов > MineCount`, счётчик показывает отрицательное значение — для отрисовки используется `minus.png` + `timer_N.png` для `N = |RemainingMines|`. Знак минуса занимает одну позицию счётчика (как в классическом Windows XP). Значение **информационное и может быть ложным** — если игрок ставит флаги не на мины.

## 16. Семантика клеток при завершении партии

Точная спецификация того, что происходит с клетками и событиями при
`Won` и `Lost`. Нужна для корректной отрисовки UI в Phase 5.

### 16.1. При `Won` (победа)

**Изменения в клетках:** **нет.** Ядро не меняет `CellState` и `CellContent`
на победе. Условие победы требует, чтобы все безопасные клетки уже были
`Opened` — ядру нечего менять.

Состояние клеток на момент `Won`:

| Тип клетки | `CellState` | `CellContent` |
|---|---|---|
| Безопасная (все) | `Opened` | `Empty` или `Number` |
| Мина, без метки | `Closed` или `Question` | `Empty` (не раскрыт) |
| Мина, с флагом | `Flagged` | `Empty` (не раскрыт) |

**События:** `GameStateChanged(NewState: Won, TriggerCell: null)` — единственное.

**Что делает UI:**
1. По событию `GameStateChanged(Won)` — перерисовывает всё поле.
2. Для каждой клетки: если `State == Closed` / `Flagged` / `Question` —
    рисует `cell_flag.png` поверх (все такие клетки гарантированно мины:
    условие победы требует, чтобы все безопасные были `Opened`).
3. Остальные — рисует по `Content` как обычно.

**Счётчик мин** — при `Won` **не изменяется**. Показывает `MineCount − количество поставленных флагов` (если игрок не ставил флагов — `MineCount`).

**Смайлик-кнопка** — переключается на `smiley_win.png` (смайлик в очках).

### 16.2. При `Lost` (поражение)

**Изменения в клетках:**

| Тип клетки | `CellState` до | `CellState` после | `CellContent` после |
|---|---|---|---|
| Триггерная (клик в мину) | `Closed` или `Question` + mine | `Opened` | `Mine` |
| Другие мины без метки | `Closed` или `Question` + mine | `Opened` | `Mine` |
| Другие мины, помеченные флагом (правильно) | `Flagged` + mine | **`Flagged` (без изменений)** | `Empty` |
| Безопасная клетка с флагом (ошибочно) | `Flagged` + safe | `WrongFlag` | `Empty` |
| Безопасная клетка с вопросом | `Question` + safe | `Question` (без изменений) | `Empty` |
| Безопасная клетка без метки | `Closed` | `Closed` (без изменений) | `Empty` |

**Ключевое правило:** правильно помеченные флаги на минах **остаются
флагами** (награда за правильную догадку). Только триггерная мина и все
непомеченные мины (включая те, что были в состоянии `Question`) открываются
как `Opened` + `Mine`.

**События:**
1. `CellChanged` — триггерная клетка (одиночное).
2. `CellsRevealed` — один батч, содержит `CellInfo` только тех клеток,
    чьё состояние **изменилось**: непомеченные мины (стали `Opened` + `Mine`)
    и ошибочные флаги (стали `WrongFlag`). Правильные флаги, вопросы на
    безопасных клетках и closed-клетки в батч **не входят** — они не менялись.
3. `GameStateChanged(NewState: Lost, TriggerCell: CellInfo триггерной клетки)`.

**Что делает UI:**
1. По `CellChanged` — триггерная клетка → `cell_exploded.png`.
2. По `CellsRevealed`:
    - `CellInfo.Content == Mine` → `cell_empty.png` + `bomb.png`;
    - `CellInfo.State == CellState.WrongFlag` → `cell_wrong_flag.png`.
3. По `GameStateChanged(Lost)` — смайлик → `smiley_lose.png`, зафиксировать
    время.

Счётчик мин при `Lost` тоже не изменяется: ошибочные флаги визуально стали `WrongFlag`, но игрок их не снимал, поэтому `RemainingMines` остаётся `MineCount − поставленные_флаги`.

### 16.3. Ассеты для отрисовки клеток

| Состояние клетки | Ассеты |
|---|---|
| `Closed` | `cell_closed.png` |
| `Flagged` | `cell_closed.png` + `cell_flag.png` |
| `Question` | `cell_closed.png` + `cell_question.png` |
| `Opened`, `Content.Empty` | `cell_empty.png` |
| `Opened`, `Content.Number` | `cell_empty.png` + `digit_N.png` (N = `AdjacentMines`, 1–8) |
| `Opened`, `Content.Mine` (не триггер) | `cell_empty.png` + `bomb.png` |
| Триггерная мина (при `Lost`) | `cell_exploded.png` |
| `WrongFlag` | `cell_wrong_flag.png` |

## 17. Аккорд (`Chord`)

**Аккорд** — это операция «открыть всех закрытых соседей клетки с цифрой,
если число флагов вокруг совпадает с цифрой». Саму клетку с цифрой операция
не открывает — она уже открыта. Аккорд бывает двух видов по триггеру:

1. **На уже открытой клетке** (ЛКМ+ПКМ, средняя кнопка, Ctrl+ЛКМ): клетка
   уже `Opened` + `Number`, аккорд сразу проверяет флаги и открывает соседей.
2. **На закрытой клетке** (двойной клик ЛКМ, Vista+): первый клик пары
   открывает клетку обычным `OpenCell`, второй клик — аккорд на уже
   открытой. С точки зрения игрока — одно действие «двойной клик»;
   технически — два вызова: `OpenCell` + `Chord`.

**Условия срабатывания `Chord` (проверяются в момент вызова):**

1. Клетка в состоянии `Opened`.
2. `Content == Number` (цифра 1–8). На `Empty` аккорда нет.
3. Количество `Flagged`-соседей == `AdjacentMines`. Точное равенство:
   больше или меньше — no-op.

**Что делает при срабатывании:**

- Открывает всех соседей в состоянии `Closed` или `Question`.
- `Flagged`-соседей не трогает.
- Empty-сосед запускает каскад (§6.3).
- Если среди открываемых соседей есть мина — поражение (§17.1).
- Если все безопасные клетки открыты — победа (§8).

**Что НЕ делает (важно для UX двойного клика):**

- Аккорд **не открывает** саму клетку с цифрой — она уже открыта.
- Аккорд **не срабатывает**, если флагов вокруг меньше или больше цифры.
  Поэтому двойной клик по **свежей** закрытой клетке без флагов откроет
  только её (первый клик), а второй клик — no-op. Чтобы двойной клик
  открыл соседей, игрок должен **заранее** расставить флаги вокруг
  (или первый клик откроет клетку с уже стоящими флагами).
- Двойной клик по закрытой клетке **с миной под ней** проигрывает на
  **первом** клике — до `Chord` дело не доходит.

**UI-триггеры аккорда:**
| Триггер | Когда работает |
|---|---|
| ЛКМ+ПКМ одновременно | Только на уже открытой клетке с цифрой |
| Средняя кнопка мыши | Только на уже открытой клетке с цифрой |
| **Двойной клик ЛКМ** | **На любой клетке.** Если она закрыта — первый клик открывает, второй делает аккорд. Если уже открыта — двойной клик сразу делает аккорд |

**Ctrl+ЛКМ — НЕ аккорд.** Это аналог правого клика (`CycleMark`) для
устройств без рабочей ПКМ. См. §7 «Метки клеток».
