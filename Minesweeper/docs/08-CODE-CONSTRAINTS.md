# 08 — Code Constraints

Жёсткие правила, вытекающие из ревью. Нарушение = баг. Агент **обязан** сверяться
с этим файлом перед объявлением задачи выполненной.

## Время

- `MinesweeperCore` **не использует** `DateTime.UtcNow`, `DateTime.Now`,
  `Stopwatch`, `Environment.TickCount`. Только `ITimeProvider` (см. `03-ARCHITECTURE.md`,
  раздел «Abstractions»).
  *Исключение — `Infrastructure/SystemTimeProvider`. Только эта реализация имеет право использовать `DateTime.UtcNow`.*
- При переходе `InProgress → Won` или `InProgress → Lost`:
  `_elapsed = Elapsed;` **до** смены `_state`. Иначе рекорд сохранится с нулевым временем.
- Тесты времени — через `FakeTimeProvider` с ручным сдвигом.

## Случайность

- `MinesweeperCore` **не использует** `new Random()`, `Random.Shared`. Только `IRandomProvider`.
  *Исключение — `Infrastructure/SystemRandomProvider`. Только эта реализация имеет право использовать `new Random()` / `Random.Shared`.*

## События

- Каскад (`RevealService.CascadeReveal`) — эмитит **ровно одно** событие `CellsRevealed`.
  **Ноль** событий `CellChanged` при каскаде.
- `CellsRevealedEventArgs.CellInfos` содержит **все** клетки, перешедшие из
  `Closed`/`Question` → `Opened`, а также ошибочные флаги (`Flagged` на безопасной → `WrongFlag`).
  `Question` на безопасной не входит — не меняется.
- Одиночный клик по `Number`/`Mine` (без каскада) — эмитит `CellChanged`, **не** `CellsRevealed`.

## Жизненный цикл

- Все публичные методы после `Dispose` → `ObjectDisposedException`.
- Первый клик вне поля (`!IsValid(point)`) **не запускает игру**: ни `PlaceMines`,
  ни `BoardGenerated`, ни `_state = InProgress`, ни таймер. Игра остаётся в `NotStarted`.

## Рекорды

- `IRecordStore.SaveRecord` возвращает `bool`. Сначала `SaveRecord`;
  только при `true` делать `_records.AddRecord(entry)`; при `false` память не трогать.
- Рекорд сохраняется **только** при `Won` и **только** для фиксированного уровня
  (`Beginner` / `Intermediate` / `Expert`). `Custom` — никогда.

## Неверные флаги

- При `Lost` клетки, помеченные флагом, но не содержащие мину, должны быть
  **отличимы** от обычных закрытых. Единственный допустимый вариант —
  новое значение `CellState.WrongFlag`.
  Просто `cell.Reset()` (как сейчас) — **запрещено**: теряется информация для UI.
- Правильно помеченные мины при `Lost` **остаются** в состоянии `Flagged`.
  Их нельзя открывать, их не нужно включать в `CellsRevealed`. Это
  «награда» игроку за правильную догадку.
- Клетки в состоянии `Question` при `Lost`:
  - если на мине → открываются как `Opened` + `Mine`;
  - если на безопасной клетке → остаются в `Question` без изменений.

## Метки клеток

- Правый клик **циклически** переключает состояние: `Closed → Flagged
  → Question → Closed`. Никогда не «перескакивает» через состояние.
- `Question` — «мягкая» метка: **не блокирует** ни `OpenCell`, ни
  `CascadeReveal`. Только `Flagged` блокирует.
- `CycleMark` разрешён в `NotStarted`: меняет метку, эмитит `CellChanged`,
  но `GameState` остаётся `NotStarted`.

## Код-стайл (мелочи, но проверяется)

- Нет `using` на собственный namespace.
- Нет мёртвых `<Compile Remove="..." />` в `.csproj`.
- `CellInfo`, `RecordEntry` — `sealed record` (не class).

## Язык комментариев — русский

**Все комментарии в коде — на русском.** Это касается:

- `///` XML-документации над классами, методами, свойствами;
- `//` обычных однострочных комментариев;
- `/* ... */` блочных комментариев;
- `// TODO:` / `// FIXME:` / `// HACK:` — тоже по-русски;
- комментариев в `.csproj`, `.props`, `.json`, `.mgcb` — по-русски.

**Имена идентификаторов** (классы, методы, переменные, свойства) — **на английском**, как принято в .NET. Русский — только в комментариях и в строках сообщений пользователю.

**Комментарий должен объяснять «почему», а не «что».** Строки `// Увеличиваем i на 1` — запрещены: код это и так говорит. `// Пропускаем мины: каскад никогда не открывает клетку с миной` — правильно.

## Комментарии в тестах — обязательны

Каждый `[Fact]` должен содержать три блока с явными комментариями:

```csharp
[Fact]
public void OpenCell_EmptyCell_TriggersCascade()
{
    // Arrange: поле 9×9, мина в правом нижнем углу, клик в левый верхний
    var engine = CreateEngine(seed: 42, mines: 1);

    // Act: открываем клетку, которая гарантированно пустая
    engine.OpenCell(new CellPoint(0, 0));

    // Assert: каскад открыл всё поле, кроме клетки с миной
    var opened = engine.GetAllCells().Count(c => c.State == CellState.Opened);
    Assert.Equal(80, opened);
}
```

**Правила для тестов:**

1. Имя метода — `Метод_Сценарий_Ожидание` на английском (`OpenCell_EmptyCell_TriggersCascade`).
2. Первый комментарий `// Arrange:` — что создаём и какие входные данные. Если используется seed — **написать, почему именно этот seed** (например, «seed 42 — мина в правом нижнем углу»).
3. Второй комментарий `// Act:` — какое одно действие выполняем.
4. Третий комментарий `// Assert:` — что проверяем и **почему именно это**.
5. Если тест сложный (каскад, граничные случаи) — комментарий должен содержать **числовые ожидания** (`9×9 с 1 миной → 80 открытых клеток`).
6. Если тест проверяет событие — указать точное количество (`CellChanged = 0, CellsRevealed = 1`).

Тест без комментариев «что делаем и почему» — **не считается выполненным**, даже если `[Fact]` и `Assert` на месте.

## Первый клик — классическое поведение

- Из расстановки мин исключается **только клетка первого клика**. Соседи
  могут содержать мины — это классическое поведение Windows XP.
- Первый клик **не гарантирует** каскадное открытие: клетка клика может
  быть `Number` (1–8), если рядом есть мины. Это норма, не баг.
- Первый клик вне поля (`!IsValid(point)`) **не запускает игру** — ни `PlaceMines`,
  ни `BoardGenerated`, ни `_state = InProgress`, ни таймер. Игра остаётся в `NotStarted`.
- Тесты на каскад не должны полагаться на «первый клик = каскад».
  Если нужен гарантированный каскад — используй `GameSettings(9, 9, 0)`
  и вручную ставь одну мину в дальний угол через
  `BoardForTesting.PlaceMines(new[] { new CellPoint(...) })`.
  **Не** используй `CellRef(x, y).IsMine = true` — это не обновит `AdjacentMines`
  у соседей, и клетки откроются как `Empty` вместо `Number`.

## Производительность

Запрещены регрессии, которые мы уже один раз чинили. Нарушение = баг.

- **`Cell` — `struct`, не `class`.** Возврат к `class` даёт N `new Cell()` и ~16-кратный рост памяти.
- **`Board.PlaceMines` обходит только мины** (O(mineCount × 8)). Возврат к полному проходу по полю (O(TotalCells × 8)) даёт ~10× больше операций на 100×100 с 10% плотности (`(10000 × 8) / (1000 × 8) = 10`).
- **`MinePlacement.PlaceMines` — partial Fisher-Yates.** Только `mineCount` swaps. Полный shuffle недопустим.
- **`RevealService.CascadeReveal` — `bool[] visited`** и инлайн-обход. Возврат к `HashSet<CellPoint>` и `yield return` даёт огромный расход памяти и аллокации `IEnumerator` на каждый обход.
- **`WinCondition.IsWon` — O(1)** через `OpenedSafeCells`. Полный проход по полю запрещён.
- **`GameEngine.RemainingMines` — O(1)** через `FlaggedCount`. Возврат `CountFlagged()` запрещён.
- **`GameEngine.OpenCell`** при каскаде строит `List<CellInfo>` только если `CellsRevealed != null`. Возврат к безусловному построению запрещён.

Регрессии ловят `PerformanceTests` (см. `07-TESTING.md` §«Производительность»).
